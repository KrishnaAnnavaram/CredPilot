# Education Loan Origination Copilot — Synthetic Data Foundation

A complete, internally consistent, entirely synthetic private education loan
origination and underwriting dataset: 200 applications, 40 fictional schools,
12 versioned policy documents, 18 applicant document artifacts, and a 20-case
golden evaluation set.

Everything here is generated by committed code from a fixed seed. Two runs
produce identical records; only the `generated_at` stamp in
`scenarios/scenario_catalog.json` differs between runs.

```bash
python synthetic_data/education/generator/generate_synthetic_data.py    # build all 200 applications
python synthetic_data/education/generator/validate_synthetic_data.py    # 17 checks, 2386 assertions
```

---

## No real data

**No record in this dataset is real, and no policy is any real lender's
policy.** The corpus is attributed to *Edgemont Education Lending*, a
fictional institution. Every name, SSN, school, employer, and account number
is invented. SSNs use the `XXX-XX-####` masked format — never a real number.

---

## Five loan products

| Code | Product | Key characteristics |
|------|---------|---------------------|
| `UG` | Undergraduate | Cosigner ~95%. Student thin-file. School certification required. |
| `GR` | Graduate | Solo borrower path if FICO >= 700 + DTI <= 40%. Federal cap $20,500/yr post-2026. |
| `SP` | Specialty/Professional | MBA, JD, MD, DDS. Residency/bar deferment. Projected income permitted. |
| `INTL` | International | F-1/J-1 visa. No-cosigner path on school tier + STEM OPT + post-study work. |
| `REFI` | Refinancing | Post-graduation. Pure consumer credit. Full income verification. |

**Product mix:** UG 80, GR 50, SP 30, INTL 25, REFI 15 = 200 total

---

## Nine-stage origination pipeline

Every application carries data supporting each stage:

0. **Intake knockouts** — age, state, school eligibility, citizenship, amount limits
1. **Identity & fraud** — KYC/CIP, SSN validation, OFAC, device/velocity, synthetic ID
2. **Credit pull** — FICO, file depth, derogatories, inquiry velocity
3. **Capacity** — income, DTI, residual income
4. **School & program risk** — cohort default rate, completion rate, program earnings
5. **Amount & certification** — school-certified COA minus aid; aggregate exposure
6. **Risk grade & pricing** — A1-E3 grades, rate, term, repayment option
7. **Decision** — APPROVE, APPROVE_WITH_CONDITIONS, REFER_MANUAL, DECLINE
8. **Compliance** — ECOA/Reg B adverse action, Reg Z disclosures, FCRA, fair lending

## Risk grade distribution

Grades A1-E3, mapped to rates 4.99%-11.99% base (POL-003). School tier C/D
adjustments add +0.50%/+1.00%.

---

## Deliberate messiness (~12% of rows)

The dataset seeds realistic data quality issues that give the copilot
something to actually work with:

- **Incomplete income docs** — `docs_complete: false`
- **Pending school certifications** — `certification_status: PENDING`
- **Unverified I-94** — `i94_verified: false` for INTL applicants
- **Address mismatches** — `address_mismatch_flag: true`
- **Missing payoff statements** — `payoff_statement_received: false` for REFI

## Post-2026 federal context

Grad PLUS was eliminated for new borrowers as of July 1, 2026. Federal caps:
- Graduate: $20,500/yr, $100,000 aggregate
- Professional: $50,000/yr, $200,000 aggregate

This drives larger private loan requests in GR and SP products.

## Consistency invariants

The validator enforces these rules (and more):

- `certified_max_eligible == COA - other_aid - federal_loans`
- `approved_amount <= certified_max_eligible` (non-REFI)
- `DTI == monthly_debt_service / monthly_gross_income`
- DECLINE has >= 1 reason code; APPROVE has none
- APPROVE_WITH_CONDITIONS has >= 1 condition
- INTL has international_details; non-INTL does not
- REFI has existing_loans; non-REFI does not
- All SSNs match `XXX-XX-####` format
- Risk grades are valid (A1-E3)

## How to regenerate

```bash
python synthetic_data/education/generator/generate_synthetic_data.py
python synthetic_data/education/generator/validate_synthetic_data.py
```

Both resolve their own paths from the script location, so they run from the
repository root and do not need a `cd` first.

The generator uses seed `20260901` for deterministic output.

---

## How to run the golden eval

The golden set in `golden_set/evaluation_cases.jsonl` provides 20 test cases.
Each case points to an application JSON and specifies the expected decision,
reason codes, policy citations, and missing documents.

Use `golden_set/rubric.md` for scoring:
- Decision correctness: 40%
- Reason code accuracy: 20%
- Policy citation accuracy: 20%
- Missing document identification: 10%
- Safety/refusal behavior: 10%
