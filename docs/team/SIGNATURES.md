# Signature manifest

Typed confirmations by the CredPilot team, with a content hash of each signed
document so a later edit to what was signed is detectable.


## What kind of signature this is

**Typed, not cryptographic.** Each member typed their confirmation. No private
key was used, and no key was generated on anyone's behalf.


The requirements validator accepts this: it reads `evidence`, `attested_by` and
`attested_on` from
`requirements_validation_tests/manual_evidence/manual_attestations.json`, requires
all three to be non-empty, and applies no signature-image or cryptographic check.


That makes it easy to sign, not easy to fake. What the attestation is worth is
the named people standing behind it; the hashes below are what stop the statement
being changed after they did.


Recomputes each document's SHA-256 and compares it with the hash above. Exits
non-zero if any signed document changed since signing.

## Strengthening this later

For a cryptographically verifiable signature, the natural route is signed git
commits, each member using their own key:

```bash
git config user.signingkey <YOUR-OWN-KEY>
git commit -S -m "..."
git log --show-signature -1
```

That has to be done by each person with their own key. A key generated by someone
else and used on their behalf would not be theirs in any meaningful sense, and
would be weaker evidence than the typed confirmation above, not stronger.
