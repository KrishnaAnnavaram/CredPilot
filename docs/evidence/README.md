# Frozen evidence extracts

Small extracts of machine-generated artifacts, kept because the artifact they
came from is *regenerated* and a citation into a regenerated file stops
resolving the moment the thing it evidences is fixed.

Nothing here is edited by hand. Each file is a verbatim subset of a committed
artifact, and `scripts/verify_evidence_citations.py` checks that the claims
[`../failure-analysis.md`](../failure-analysis.md) makes about these files are
still true.

| File | Extracted from | Evidences |
|---|---|---|
| `f14-intake-spans.jsonl` | `traces/phoenix_spans.jsonl`, run `5cccfeb6ce324c37a25885f1675b7337`, 980 spans / 278 traces | F-14 — all 14 `graph.intake` spans of that run, including `d95923312aa55be9` at 31,107 ms against a 4.0 ms p50 for the same node |

**Why F-14's evidence had to be frozen.** The trace export is regenerated by
`scripts/export_traces.py`, and the exporter now waits for the redaction
warm-up before it traces anything — so the cold start F-14 is about no longer
appears in the current export, which is the point of the fix. The run that
caught it is preserved here rather than being re-created, because re-creating
it would mean re-introducing the bug.
